Lab

real output, not screenshots

A couple of the tools in action. The audit is consolebugs pointed at my own live site; the config is the routing table BasicLLM uses to pick a provider per request.

consolebugs — audit kwen.in
pwsh -c ./consolebugs.ps1 -Target https://kwen.in phase 01 dns ok 4 records · 0 dangling phase 02 tls tls1.3 · h2 · hsts on phase 03 headers 3 findings phase 04 ports filtered · 22,443 open phase 05 cors 1 misconfiguration phase 06 injection clean · 0 candidates phase 07 fingerprint next.js · vercel edge 14 phases · 31 checks · 0.9s → audit-4f2a.html
basicllm.config.json 
// route per request, learn which provider is actually up
{
  "strategy": "ucb1",
  "stickySessions": true,
  "circuitBreaker": {
    "failThreshold": 3,
    "cooldownMs": 30000
  },
  "providers": [
    { "id": "groq",       "weight": 1.0 },
    { "id": "cerebras",   "weight": 0.9 },
    { "id": "openrouter", "weight": 0.7 },
    { "id": "local-ollama","weight": 0.4 }
  ]
}

Everything above runs locally. No keys required for the audit — the gateway needs a provider, and will happily fall back to Ollama on the same machine.

About

I work on three things that happen to overlap: security research, AI/LLM infrastructure, and developer tooling. Most projects start because I needed the tool to exist, then keep going because other people needed it too.

The through-line is making hard things usable without heavy infrastructure. Model compression that runs on a laptop. Web scraping that turns a site into a shell command. Security audits that output a report a human can actually read and hand to someone.

Kwen is the exception — a real product with real people on it, built in the open. Everything else here is public and permissively licensed. If something saves you an evening, the source is one click away.
